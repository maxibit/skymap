# Repository Structure

The project uses two repositories with different responsibilities
([ADR-0009](adr/0009-separate-app-and-gitops-repositories.md)):

| Repository | Contains | Changes when |
|---|---|---|
| `kasa-energy-monitor` | Application source, tests, Dockerfile, Helm chart, dashboard, docs | The software changes |
| `homelab-gitops` | Desired state of the whole cluster: Argo CD Applications, values, secrets | What runs in the cluster, or which version, changes |

Releasing a new version of the application is a change in `kasa-energy-monitor`;
**deploying** it is a separate, reviewable change in `homelab-gitops`.

Conventions:

- `cmd/` contains no logic — only wiring. Everything testable lives in `internal/`.
- `internal/` prevents other modules from importing the packages; this is an application,
  not a library.
- Test fixtures live next to the code that uses them (`testdata/` is ignored by the Go tool).
- The dashboard is owned by the application and shipped with its chart, so the dashboard
  version always matches the metrics version.

### Artifacts produced

| Artifact | Location |
|---|---|
| Container image | `ghcr.io/<user>/kasa-energy-monitor:<version>` (`linux/amd64`, `linux/arm64`) |
| Image signature and SBOM attestation | Stored next to the image in GHCR (cosign) |
| Helm chart | `oci://ghcr.io/<user>/charts/kasa-energy-monitor` |
| Release notes | GitHub Releases + `CHANGELOG.md` |

## `homelab-gitops` (cluster state repository)

```
homelab-gitops/
├── bootstrap/
│   └── root.yaml                   # root Application — the only manual kubectl apply
├── projects/
│   ├── platform.yaml               # AppProject for cluster components
│   └── apps.yaml                   # AppProject for applications
├── apps/                           # one Argo CD Application per component
│   ├── argocd.yaml
│   ├── sealed-secrets.yaml
│   ├── kube-prometheus-stack.yaml
│   ├── cloudflared.yaml
│   ├── tplink-plug-exporter.yaml   # legacy, removed in Phase 6
│   └── kasa-energy-monitor.yaml
├── values/                         # Helm values per component
│   ├── argocd.yaml
│   ├── sealed-secrets.yaml
│   ├── kube-prometheus-stack.yaml  # includes Alertmanager routes and the Pushover receiver
│   ├── cloudflared.yaml
│   └── kasa-energy-monitor.yaml    # plug list, Access audience, alert thresholds
├── manifests/                      # plain manifests that are not part of a chart
│   ├── namespaces/
│   │   ├── kasa.yaml               # with Pod Security labels
│   │   └── cloudflared.yaml
│   └── secrets/                    # SealedSecret objects only — never plain Secrets
│       ├── cloudflared-tunnel-token.yaml
│       ├── grafana-admin.yaml
│       └── alertmanager-pushover.yaml   # Pushover user key + application token
├── terraform/                      # optional: Cloudflare Zero Trust as code
│   └── cloudflare/                 # tunnel routes, Access applications and policies
├── renovate.json                   # proposes chart and image version bumps
└── README.md                       # how to bootstrap the cluster from scratch
```

Conventions:

- Applications that deploy a third-party chart use **multiple sources**: the chart from its
  Helm/OCI repository and the values file from this repository (`$values` reference).
- Every chart version and image is pinned; Renovate opens a PR to change it.
- Sync order is controlled with `argocd.argoproj.io/sync-wave`:

| Wave | Components |
|---|---|
| `-10` | Namespaces, Sealed Secrets |
| `-5` | kube-prometheus-stack (CRDs and operator) |
| `0` | cloudflared, kasa-energy-monitor, legacy exporter |

- Nothing in this repository is applied by hand except `bootstrap/root.yaml`.
